# SoundBox

Экспериментальное приложение на **Java 21 + Swing**, демонстрирующее **LSB-стеганографию в несжатом аудио** в сочетании с **AES-256** шифрованием.

Проект является аудио-аналогом `stegobox`:

```text
stegobox: текст прячется в PNG/BMP через младшие биты каналов R, G, B
soundbox: текст прячется в WAV/PCM через младшие биты аудиосэмплов
```

---

## Важная позиция по форматам

Текущая версия использует:

```text
WAV / PCM 16-bit little-endian
```

MP3 напрямую не используется для скрытия данных методом LSB.

Если у вас есть `.mp3`, сначала сконвертируйте его в WAV:

```bash
ffmpeg -i input.mp3 -c:a pcm_s16le -ar 44100 -ac 2 input.wav
```

Затем загружайте полученный `.wav` в SoundBox.

---

## Возможности

- **Графический режим** на Swing + FlatLaf.
- **Консольный режим** по аналогии со `stegobox`:
  - если приложению переданы аргументы, запускается CLI;
  - если аргументов нет, открывается графический интерфейс.
- **Скрытие текста в аудио** методом LSB: младший бит каждого 16-битного сэмпла заменяется битом зашифрованного сообщения.
- **Шифрование текста**:
  - `AES-256/GCM`;
  - ключ получается из пароля через `PBKDF2-HMAC-SHA256`;
  - 120 000 итераций;
  - случайный `salt`;
  - случайный `IV`.
- **Извлечение текста** из аудио по паролю.
- **Проверка ёмкости** до встраивания.
- **Автоматическое сохранение результата** рядом с исходным файлом:

```text
<имя>_stego.wav
```

- **Асинхронная обработка** в GUI через `SwingWorker`.

## Использование в GUI

### Скрыть текст

1. Нажмите **Обзор...**.
2. Выберите WAV-файл.
3. Введите текст для сокрытия.
4. Введите пароль.
5. Нажмите **Скрыть текст в аудио**.
6. Рядом с исходным файлом появится результат:

```text
<имя>_stego.wav
```

### Извлечь текст

1. Нажмите **Обзор...**.
2. Выберите WAV-файл со скрытым текстом.
3. Введите пароль.
4. Нажмите **Извлечь текст из аудио**.
5. Текст появится в центральном поле.

## Консольный режим

Кроме GUI, поддерживается консольный режим.

Если приложению переданы аргументы, автоматически запускается CLI.

### Команды

```text
soundbox hide    -i <audio> -t <text> | --text-file <file> -p <password> [-o <out>]
soundbox extract -i <audio> -p <password> [-o <out.txt>]
soundbox help
soundbox version
```

### Общие параметры

```text
-i, --input    <file>   входной аудиофайл
-p, --password <pw>     пароль
-o, --output   <file>   выходной файл
```

Поведение `--output`:

- для `hide`:
  - если не указан, создаётся файл рядом с исходником:
    ```text
    <имя>_stego.wav
    ```
- для `extract`:
  - если не указан, текст печатается в `stdout`.

### Только для `hide`

```text
-t, --text      <text>  текст для сокрытия; "-" означает чтение из stdin
    --text-file <file>  прочитать текст из файла в кодировке UTF-8
```

### Пароль

Пароль можно задать несколькими способами:

1. Параметром:

```bash
-p password
```

2. Переменной окружения:

```bash
export SOUNDBOX_PASSWORD="password"
```

3. Интерактивно:

```bash
soundbox hide -i input.wav -t "секрет"
```

Если пароль не задан и есть консоль, приложение запросит его через:

```java
System.console().readPassword()
```

После использования массив пароля затирается.

### Примеры

Скрыть строку:

```bash
soundbox hide -i audio.wav -t "секрет" -p qwerty
```

Скрыть текст из файла:

```bash
soundbox hide -i audio.wav --text-file secret.txt -p qwerty
```

Скрыть текст из `stdin`:

```bash
cat secret.txt | soundbox hide -i audio.wav -t - -p qwerty
```

Извлечь текст в `stdout`:

```bash
soundbox extract -i audio_stego.wav -p qwerty
```

Извлечь текст в файл:

```bash
soundbox extract -i audio_stego.wav -p qwerty -o secret.txt
```

Показать версию:

```bash
soundbox version
```

## Как это работает

### 1. Аудио приводится к 16-битному PCM

Для встраивания используется несжатый PCM-поток:

```text
16 бит на сэмпл
```

Это даёт понятный и предсказуемый формат данных.

### 2. Текст шифруется

Перед встраиванием текст шифруется:

```text
password ──PBKDF2-HMAC-SHA256──▶ AES-256 key
plaintext ──AES-256/GCM──▶ salt ‖ IV ‖ ciphertext ‖ tag
```

`GCM` обеспечивает:

- конфиденциальность;
- целостность;
- проверку подлинности данных.

Если пароль неверный или данные были изменены, расшифровка завершится ошибкой.

### 3. Шифрованные байты прячутся в аудио

Используется один бит на каждый 16-битный сэмпл:

```text
sample: xxxxxxxxxxxxxxx?
               ^
               сюда прячется один бит полезной нагрузки
```

Так как используется `little-endian` PCM, младший байт сэмпла идёт первым.

---

## Формат скрытых данных

```text
[4 байта: длина payload] [payload]
```

`payload`:

```text
[16 байт salt][12 байт IV][шифротекст + 16 байт GCM-тега]
```

Служебный размер:

```text
4 + 16 + 12 + 16 = 48 байт
```

---

## Ёмкость

Формула:

```text
capacity_bytes = pcm_bytes / 16
```

Пояснение:

```text
16-битный сэмпл занимает 2 байта;
мы прячем 1 бит в один сэмпл;
8 бит = 1 байт полезной нагрузки;
значит 8 сэмплов = 16 байт PCM.
```

Для аудио:

```text
44.1 kHz, 16 bit, stereo
```

ёммкость составляет примерно:

```text
10.8 КБ в секунду
```

Для трека длиной 3 минуты:

```text
≈ 1.9 МБ скрытого текста
```

## Почему не используется прямой режим для MP3?

MP3 — это формат с потерями.

Если сначала спрятать данные в исходных сэмплах, а затем сохранить результат в MP3, аудиокодек может изменить почти всё:

- частотные компоненты;
- сэмплы;
- квантованные коэффициенты;
- битпоток.

Поэтому прямой `LSB → MP3` в общем случае не выживет.

Если вам нужен именно входной файл `.mp3`, правильный текущий путь такой:

```text
MP3 → WAV → SoundBox → WAV
```

Пример:

```bash
ffmpeg -i input.mp3 -c:a pcm_s16le -ar 44100 -ac 2 input.wav
```

## Безопасность

- Текст не сохраняется и не логируется.
- Пароль нигде не хранится.
- После использования массив символов пароля затирается:

```java
Arrays.fill(password, '\0');
```

- Для шифрования используются:
  - `AES-256/GCM`;
  - `PBKDF2-HMAC-SHA256`;
  - случайные `salt` и `IV`.

Один и тот же текст с одним и тем же паролем при повторном скрытии даёт разные байты, потому что каждый раз генерируются новые `salt` и `IV`.

## Важные ограничения

Результат нужно использовать как несжатый аудиофайл.

Скрытый текст может быть потерян, если аудио:

- перекодировать в формат с потерями;
- сохранить в MP3;
- изменить громкость;
- нормализовать;
- обрезать;
- ускорить или замедлить;
- изменить частоту дискретизации;
- обработать шумоподавлением;
- пересжать в формате с потерями.

Для надёжности используйте:

```text
WAV / PCM
```

или другой несжатый формат / формат без потерь.

## Структура проекта

```text
src/main/java/ru/mcs/
 ├── Main.java          # точка входа; при наличии аргументов запускает CLI, иначе GUI
```
